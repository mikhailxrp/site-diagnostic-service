# Правила дизайна и UI — Site Diagnostics (Tabler 1.6.1)

## Принцип интерфейса

Все экраны проекта собираются из стандартных компонентов локального **Tabler 1.6.1** и **Tabler Icons 3.52.0**.
Отдельной публичной части, дизайн-прототипов (`.docs/ref/prototypes/`) и `tokens.json` (`.docs/design/`) в проекте нет — это зафиксированное решение владельца.

## Где что лежит

```text
public/assets/
├── vendor/tabler/           ← локальный Tabler 1.6.1 + Tabler Icons 3.52.0 (руками не править)
├── css/
│   ├── admin-theme.css      ← минимальные переопределения темы (подключается ПОСЛЕ tabler.min.css)
│   └── print.css            ← стили для печати и экспорта в PDF
└── js/                      ← Vanilla JS (diagnostic-progress.js, history.js)

src/Views/
├── admin/layout/            ← общий макет: header.php, footer.php
├── pages/                   ← страницы приложения (home, diagnostic, client-report, compare, history, settings)
└── components/              ← переиспользуемые фрагменты (flash, finding, ai-block, stack-item, checkout-steps, screenshot-gallery)
```

## Стили и разметка

- Подключаемый порядок CSS задан в `src/Views/admin/layout/header.php`: `tabler.min.css` → `tabler-icons.min.css` → `admin-theme.css` → `print.css`.
- Используй готовые классы и компоненты Tabler (карточки, таблицы, бейджи, alert, формы, кнопки, адаптивная сетка). Не создавай собственные CSS-компоненты без явной необходимости.
- Не пиши inline-стили (`style=""`) и теги `<style>` внутри Views.
- Не редактируй файлы в `public/assets/vendor/tabler/` и не обновляй Tabler вручную по частям.
- Избегай `!important`, кроме обоснованных правил печати/переопределений в `print.css`.

## Шаблоны, данные и безопасность

- Шаблоны получают готовые массивы от контроллеров — никаких SQL-запросов и вызовов сервисов внутри Views.
- Все выводимые динамические значения экранируются через `e()`.
- Все POST-формы содержат `<?= csrfField() ?>`.
- Уведомления об успехе и ошибках выводятся через флеш-сообщения (`setFlash()` / `getFlash()`, компонент `src/Views/components/flash.php`).
- Длинные URL, пути и тексты ошибок не должны ломать сетку и вызывать горизонтальную прокрутку (используй классы переноса Tabler/CSS).

## Режим PDF / печати

- Страницы, участвующие в PDF-экспорте (`diagnostic.php`, `client-report.php` и общие компоненты), обязаны учитывать флаг `$isPdfExport` и класс `d-print-none`.
- В PDF-режиме скрываются навигация, кнопки действий, формы, прогресс, вкладки и модальные окна; контент выводится статично без JavaScript.

## Обязательные состояния и проверка UI

Каждый новый или изменённый экран должен корректно обрабатывать применимые состояния:
- обычное состояние с данными;
- пустое состояние (понятный текст, без пустых «сломанных» блоков);
- состояние ошибки (флеш без stack trace, без полупустого рендера);
- частичный отчёт (`failed` диагностика — явное предупреждение о неполноте данных);
- состояние загрузки / прогресса (если применимо).

Перед завершением UI-задачи проверь экран в реальном браузере (в Antigravity — через встроенного `browser`-субагента или headless Chrome; в Claude Code — через Playwright MCP или headless Chrome):
1. Ширины **360 px**, **768 px** и **1280 px**: нет сломанной вёрстки и горизонтальной прокрутки.
2. Интерактивные кнопки и ссылки имеют зону нажатия не меньше **44 px**.
3. В консоли браузера нет JS-ошибок и упавших локальных ресурсов.
4. Временные скриншоты/артефакты проверки удалены.
