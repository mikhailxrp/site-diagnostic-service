# Pipeline — Site Diagnostics

## Точка входа (Antigravity и Claude Code)

Единый регламент проекта находится в `AGENTS.md`:
- **Antigravity** загружает `AGENTS.md` автоматически;
- **Claude Code** автоматически загружает `CLAUDE.md`, который импортирует `@AGENTS.md`, а также правила из `.claude/rules/*.md`.

Ручное копирование промптов и отдельные команды для перехода между шагами не требуются.

- Текущий статус фаз и проектные решения: `.docs/phases/_status.md`.
- Контракт активного планового таска: `TASK.md`.

## Автономный цикл

1. Определить тип задачи: плановый таск (`_status.md`, `phase-N.md`, `TASK.md`) или отдельная правка/багфикс от пользователя.
2. Прочитать обязательные правила (`.claude/rules/general.md`, `php.md`, `design.md`) и `.docs/dod-global.md` для затрагиваемых слоёв.
3. Сверить план с фактическим кодом и существующими тестами.
4. Для нового планового таска (если его ещё нет) подготовить `TASK.md` по `.docs/prompts/task-init.md` и `TASK-example.md`. Для отдельного багфикса `TASK.md` не перезаписывать.
5. Реализовать задачу в пределах `Scope` без лишних запросов подтверждения на обычные локальные действия.
6. Проверить DoD по `.docs/prompts/dod-check.md`: PHPUnit на PHP 8.3 OpenServer (`& "C:\OSPanel\modules\PHP-8.3\PHP\php.exe" vendor/bin/phpunit`), реальный сценарий E2E, UI на 360/768/1280 px и `storage/logs/app.log` — где применимо.
7. При полном прохождении DoD обновить `TASK.md` и статусы фазы (для планового таска) и добавить запись сверху в `.docs/dev-log.md`.
8. Переходить к следующему таску только в рамках запроса пользователя; не начинать новый объём работы молча.

## Планирование

- Новая или перепроверяемая фаза — по регламенту `.docs/prompts/phase-init.md`.
- Новый активный таск — по регламенту `.docs/prompts/task-init.md`.
- Если пользователь просил создать или обновить документ, агент делает это сразу. Подтверждение нужно только при неоднозначном продуктовом решении или изменении согласованных границ.

## Конец работы

Задача считается завершённой только после реализации и проверки. Красные тесты, невыполненный сценарий или непроверенные обязательные критерии нельзя скрывать: задача остаётся открытой, а ограничения явно фиксируются в итоговом ответе.
