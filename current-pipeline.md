# Pipeline — Site Diagnostics

## Точка входа

Агент начинает с `AGENTS.md`. Ручное копирование промптов и отдельные команды для перехода между шагами не требуются.

Текущий статус фаз: `.docs/phases/_status.md`.
Текущий контракт реализации: `TASK.md`.

## Автономный цикл

1. Определить активную фазу и таск по `_status.md`, `phase-N.md` и `TASK.md`.
2. Прочитать обязательные правила и относящуюся к задаче документацию.
3. Сверить план с фактическим кодом и существующими тестами.
4. Если активного таска нет, подготовить `TASK.md` по `.docs/prompts/task-init.md` и `TASK-example.md`.
5. Реализовать задачу в пределах Scope без запроса подтверждения на обычные локальные действия.
6. Проверить DoD по `.docs/prompts/dod-check.md`: тесты, реальный сценарий, UI и логи — где применимо.
7. При полном прохождении DoD обновить `TASK.md`, статусы фазы и `.docs/dev-log.md`.
8. Перейти к следующему таску только в рамках запроса пользователя; не начинать новый объём работы молча.

## Планирование

- Новая или перепроверяемая фаза — по регламенту `.docs/prompts/phase-init.md`.
- Новый активный таск — по регламенту `.docs/prompts/task-init.md`.
- Если пользователь просил создать или обновить документ, агент делает это сразу. Подтверждение нужно только для неоднозначного продуктового решения или изменения согласованных границ.

## Конец работы

Задача считается завершённой только после реализации и проверки. Красные тесты, невыполненный сценарий или непроверенные обязательные критерии нельзя скрывать: таск остаётся открытым, а ограничения фиксируются в итоговом ответе.
