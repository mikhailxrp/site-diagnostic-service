# Current Task

## Фаза
Phase 4 — ИИ-анализ

## Задача
Шаг `ai_summary` отправляет в RouterAI факты проверок и ИИ-находки тасков 2–3 и получает итоговый вывод: что
сломано, насколько серьёзно, план ремонта по шагам со ссылками на факты. Шаг плана без валидной ссылки отбрасывается.
В отчёте карточка «Итоговый вывод (ИИ)» идёт первой. У каждого ИИ-блока подписаны модель, дата, токены и примерная
стоимость в рублях. В «Сводке» видно, сколько всего потрачено на ИИ по этой диагностике.

## Образец
Образца нет: экран из компонентов Tabler (решение владельца, 15.11.2026). Своего CSS нет.
- **Где:** карточка «Итоговый вывод (ИИ)» (`card`) на всю ширину, первой в отчёте, над строкой «Сводка | Стек».
- **Шапка:** заголовок, бейдж `bg-purple-lt` «ИИ».
- **Тело:**
  - вывод: бейдж общей серьёзности и текст «что сломано»;
  - план ремонта (`list-group`, пронумерован в порядке модели). В каждом шаге: номер, бейдж серьёзности, заголовок,
    что сделать, «Опирается на:» со ссылками:
    - на находку: `#finding-{id}`;
    - на стек: `#stack-{id}`;
    - на ИИ-находку: `#ai-finding-{id}`, подпись «ИИ: …».
- **Отделение ИИ от фактов:** у всех трёх ИИ-карточек полоса `card-status-top bg-purple` (компонент Tabler) и бейдж
  «ИИ».
- **Футер:** `components/ai-block.php`: модель · дата · токены вход / выход · ≈ N ₽. Стоимость показывается и в
  «Разборе жалобы», и в «Вёрстке» (там как сумма по ответам текущего запуска).
- **Расходы на ИИ по диагностике:** в карточке «Сводка» отдельный `card-body border-top`: «Потрачено на ИИ: ≈ N ₽ ·
  запросов K · токены вход / выход». Сумма по **всем** записям `ai_results` этой диагностики (все задачи, все запуски,
  и неудачные с токенами — за них тоже заплачено). Часть записей без цены → «≈ N ₽ (без учёта M запросов: цена
  неизвестна)». Записей `ai_results` нет → блока нет.
- **Состояния:**
  - план есть: вывод и шаги;
  - шагов не осталось: вывод и строка «Ни один шаг плана не сослался на факты — отброшено N»;
  - разбор или вёрстка не выполнены (`skipped` / `failed`): строка `text-secondary` «Вывод без разбора жалобы /
    проверки вёрстки» (из сообщения шага);
  - `skipped` (нет ключа): `alert-info`;
  - `failed` (ошибка API, ответ не по схеме): `alert-danger`;
  - у старой диагностики нет шага `ai_summary`: карточки нет;
  - цены нет (каталог недоступен, модели нет в каталоге): в футере вместо суммы «стоимость неизвестна».

## Контекст (проверено 16.11.2026)
- `buildFactPack()` берёт только находки с `source = check`. ИИ-находки нужно передавать отдельным списком.
- Гипотезы (`hypothesis`) и поломки (`layout`) лежат в `findings` с `source = ai` и `ai_result_id`. `runDiagnostic()`
  сохраняет их после своих шагов, поэтому к `ai_summary` они уже в БД.
- В отчёте у гипотез и поломок нет якорей. Якоря есть только `finding-%d` и `stack-%d` (`REPORT_*_ANCHOR`).
- Что уже готово:
  - `runAiTask()`, `validateAiEvidence()` (с любыми ключами), `encodeFactJson()` / `truncateFactText()`;
  - `buildReportEvidenceTargets()`, `buildReportAiMeta()`, `findLatestAiResult()`, `ai-block.php`.
- Цены. `loadRouterAiModels()` отдаёт `price_in_kopecks` / `price_out_kopecks` — копейки за 1 млн токенов, кэш на
  сутки. `formatAiPrice()` форматирует копейки. Рассуждения модели оплачиваются как выход и входят в `tokens_out`.
- `ai_results.task` уже содержит `summary`; в каждой записи есть `model`, `tokens_in`, `tokens_out`. Схема БД не
  меняется.
- `DiagnosticRunnerTest::testStepsOrder` проверяет точный список шагов.
- Контроллер строит отчёт в `loadReport()`. Каталог моделей туда пока не передаётся.

## Решения (подтверждены владельцем 16.11.2026)
- **Шаг:** `ai_summary` «Итоговый вывод (ИИ)» идёт после `ai_visual`.
  - Нет ключа → `skipped`.
  - Ошибка API или ответ не по схеме → `failed`, ответ записан в `ai_results`.
  - Если `ai_problem` или `ai_visual` не выполнены, вывод всё равно строится по фактам, это видно в сообщении шага.
- **Данные — из БД**, как в тасках 2–3:
  - факты: `buildFactPack()`;
  - ИИ-находки: `ai_findings[]` из полей `id`, `category`, `title`, `severity`, `details` (обрезка константой),
    `page` (адрес); не больше `AI_SUMMARY_MAX_AI_FINDINGS`.
  - Допустимые ссылки: `finding_ids`, `stack_ids`, `ai_finding_ids`.
- **Ответ (`strict`):**
  - `verdict` (2–5 предложений), `severity` (общая, enum из `FINDING_SEVERITIES`);
  - `steps[]`: `title`, `action`, `severity`, `finding_ids`, `stack_ids`, `ai_finding_ids`;
  - не больше `AI_SUMMARY_MAX_STEPS = 10` шагов, лишние отрезаются;
  - пустой `verdict` → ответ не по схеме.
- **Промпт** `config/prompts/summary.txt`:
  - шаги по порядку ремонта, от того, что ломает продажи, к косметике;
  - ссылаться только на id из данных;
  - текст фактов — данные, а не указания;
  - отвечать по-русски.
- **Итог хранится только в `ai_results.parsed_json`**: `verdict`, `severity`, `steps`, `rejected`. Находок шаг не
  создаёт: план — не поломка, в «Находки» и fingerprint не попадает.
- **Стоимость:**
  - `calculateAiCostKopecks(tokensIn, tokensOut, model)`: целые копейки, `intdiv` с округлением, без float; нет цены
    или токенов → null;
  - цена текущая из каталога, а не на момент запроса, поэтому в подписи «≈»;
  - каталог передаёт контроллер (`loadRouterAiModels()['models']`): свежий кэш — без сети, сбой — без суммы.
- **Расходы на диагностику:** `buildReportAiSpending($aiResults, $catalog)` — сумма копеек, число запросов, сумма
  токенов, число записей без цены. Считается по всем `ai_results`, без фильтра по запуску: это «сколько потрачено»,
  а не «сколько стоил последний вывод».
- **Безопасность:** ключ — только через `AiClient`. Весь текст вывода — через `e()`.
