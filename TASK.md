# Current Task

## Фаза
Phase 5 — Для клиента и углублённые проверки (таск 3 — Сценарий корзины в отчёте) — ✅ Завершён

## Задача
В готовом техническом отчёте показывается карточка «Сценарий заказа»: достигнутые шаги «Товар → В корзину →
Корзина → Оформление», место остановки, безопасная статистика изменяющих запросов, ошибки консоли и отдельный
скриншот каждого шага; сохранённый `summary_json.checkout` остаётся доступен ИИ как проверяемый факт.

## Образец
Утверждённого HTML-прототипа нет. По решению владельца от 15.11.2026 экран собирается только из стандартных
компонентов локального Tabler: `card`, `list-group`, `badge`, `alert`, существующая галерея скриншотов и модальные
окна. Новые CSS и JS не добавляются.

## Как это работает
1. **Источник данных** — только `summary_json.checkout`, который сохранил таск 2, и переданные в `buildReport()`
   строки `screenshots`. Запросов к БД во View нет.
2. **Когда есть карточка.**
   - Есть массив `summary_json.checkout` с шагами → `ReportBuilder` возвращает `report.checkout`, View показывает
     карточку.
   - У старой диагностики нет раздела `checkout` или он повреждён → `report.checkout = null`, карточки нет.
   - Ранний `skipped` без запуска Chrome (не найден товар, нет библиотеки / Chrome) уже виден в «Не удалось
     проверить»; пустая карточка для него не создаётся.
3. **Итог карточки.** В заголовке — общий статус и бейдж:
   - `reached` → «Форма оформления открылась» (`bg-green-lt`);
   - `failed` → «Сценарий остановился» (`bg-red-lt`);
   - `skipped` → «Проверка пропущена» (`bg-yellow-lt`).
   Ниже — последний достигнутый шаг (`reached`) и статистика `posts`: сколько изменяющих запросов заблокировано и
   сколько ушло. Если `checkout_sent > 0`, выводится `alert-danger`; нормальный результат явно говорит «ушло 0».
4. **Шаги.** Порядок и состав берутся из `summary.checkout.steps`; известные коды получают подписи «Товар»,
   «В корзину», «Корзина», «Оформление», неизвестный код не ломает отчёт и выводится безопасной строкой. Для шага:
   - бейдж `done / failed / skipped` через готовые подпись и Tabler-класс из `ReportBuilder`;
   - адрес и `note`, если они есть;
   - число ошибок консоли и первые `console_sample`; при нуле — спокойная подпись «Ошибок консоли нет»;
   - скриншот 1366 через существующий `components/screenshot-gallery.php`; если файла / строки `screenshots` нет —
     понятное пустое состояние без битой картинки.
5. **Безопасность данных.** `screenshot_id` из JSON используется только если такой id присутствует среди строк
   `screenshots`, переданных для этой диагностики. Все тексты и адреса во View проходят через `e()`.
6. **Факты для ИИ.** `packSummaryFacts()` уже переносит все разделы сводки, кроме явно исключённых `databases`,
   поэтому `summary.checkout` уже попадает в `ai_problem` / `ai_summary`. `FactPacker.php` не меняется; тест
   закрепляет наличие раздела и ограничение `FACT_SECTION_MAX_CHARS`. Страницы сценария по-прежнему исключает
   реализованный в таске 2 `excludeCheckoutPages()`.
