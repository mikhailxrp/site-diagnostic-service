# Current Task

## Фаза
Phase 3 — Проверка в браузере

## Задача
Каждая проверенная страница загружается на ширинах 360 / 768 / 1366. Во время загрузки собираются необработанные
исключения, ошибки консоли, запросы с сетевой ошибкой и с ответом 4xx/5xx. Из них получаются находки `js_error` /
`failed_request` со страницей, файлом, строкой и ширинами. Ложные срабатывания отсекаются правилами ниже.

## Образец
Образца нет: используется существующий компонент находки `src/Views/components/finding.php` на компонентах Tabler
(решение владельца, 15.11.2026). Новых блоков в отчёте нет. Находки показываются в общем списке и в «Находках по
страницам», в компонент добавляются строка «Где: файл, строка N» и «Ширины: 360, 768 px».

## Контекст (проверено 16.11.2026)
- Сейчас каждая страница открывается только на 1366. Фаза требует собирать ошибки со всех трёх ширин, поэтому
  загрузка на 360 / 768 / 1366 входит в этот таск. Таск 3 потом добавит к этим загрузкам скриншоты.
- Шаг `browser` не видит находки других шагов, ему доступны только факты (`$context['facts']`). Чтобы не дублировать
  `broken_resource`, отсеиваем по `facts.resources.resources`: это ресурсы с кодом ошибки или без ответа.
- Проверка URL (`UrlValidator`) не пускает диагностику на локальные адреса. Поэтому синтетическая проверка
  `Uncaught TypeError` идёт разовым CLI-вызовом `openBrowserPage()` на странице-фикстуре, а живая — на реальных
  сайтах.
- `js_error` / `failed_request`, их серьёзность по умолчанию в `FindingFactory.php` и подписи категорий в
  `ReportBuilder.php` уже есть.

## Решения
- **Ширины:** константа `BROWSER_VIEWPORT_WIDTHS = [360, 768, 1366]`, высота окна 768. Каждая загрузка идёт в новой
  вкладке, перед навигацией вызывается `Emulation.setDeviceMetricsOverride`. Для 360 ставится `mobile: true`, чтобы
  учитывался `<meta viewport>`. User-Agent не подменяется (как в таске 1). Heartbeat обновляется после каждой
  загрузки, а не после каждой страницы.
- **События** (подписка до `Page.navigate`, собираются в том же цикле ожидания):
  - `Runtime.exceptionThrown`: необработанное исключение. Берутся сообщение, файл, строка, столбец и до 5 кадров
    стека.
  - `Runtime.consoleAPICalled` с `type = error`: `console.error` из кода сайта.
  - `Log.entryAdded` с `level = error`, только неисключённые источники (см. «Ложные срабатывания»).
  - `Network.loadingFailed`: сетевая ошибка (`errorText`, `canceled`, `blockedReason`).
  - `Network.responseReceived` со статусом ≥ 400.
- **Ожидание после `load`:** до `BROWSER_SETTLE_MS = 2000`, чтобы поймать ошибки из таймеров и отложенных скриптов.
  Если `load` не наступил, то же время отсчитывается от `DOMContentLoaded`. События, пришедшие после окончания
  ожидания (в том числе при закрытии вкладки), не учитываются.
- **Ограничение событий:** не больше `BROWSER_MAX_EVENTS_PER_LOAD = 200` на одну загрузку (константа), чтобы
  бесконечный цикл ошибок не раздул факты.
- **Склейка** (`Checks/BrowserConsoleCheck.php`, только чистые функции):
  - одинаковая ошибка (тип + сообщение + файл + строка; у запроса — адрес + код или `errorText`) со всех страниц и
    ширин даёт одну находку;
  - в `evidence` лежат `pages`, `widths`, `count`, `line`, `column`, `stack` / `status`, `error_text`,
    `resource_type`, `recheck` (результат повторного запроса);
  - fingerprint строится из адреса файла (или страницы, если скрипт встроенный) и ключа ошибки. В сообщении ошибки
    перед сравнением числа-идентификаторы не трогаются: склейка только точных совпадений.
- **Серьёзность** (через `$severity` в `makeFinding()`, значения по умолчанию в `FindingFactory` не меняются):
  - необработанное исключение в файле своего домена или во встроенном скрипте — `medium`, в файле чужого домена —
    `low`;
  - `console.error` и ошибка из `Log` — `low`;
  - упавший запрос на своём домене — `medium`, на чужом — `low`.
  «Свой домен» — хост страницы и его поддомены, без `www.` (как в `ResourceCheck`).
- **Заголовки:** «Ошибка JS: Uncaught TypeError: Cannot read properties of undefined (reading 'foo')», «Упавший
  запрос: код 404» / «Упавший запрос: net::ERR_CONNECTION_REFUSED».
- **Сообщение шага:** «Открыто в браузере: 4 из 4 страниц (12 загрузок); ошибок JS: 3; упавших запросов: 2;
  пропущено (защита от ботов): 1».
- **Факты шага:** по каждой загрузке хранятся статус, `dom_ms`, `load_ms`, ширина и число событий (принятых и
  отброшенных — по причинам). Сырые события в факты не пишутся, только в `evidence` находок.

## Ложные срабатывания — что не становится находкой
Каждое правило — отдельная чистая функция или запись в `data/browser-ignore.php`, на каждое — тест.

**Общее**
- Хосты счётчиков, рекламы и виджетов из `data/browser-ignore.php` (Яндекс.Метрика, GA / GTM, DoubleClick,
  VK / Mail.ru top, Facebook, Calltouch, Roistat и т. п.): их запросы и исключения в их файлах (по файлу исключения
  или верхнему кадру стека) не учитываются. Список пополняется без правки кода.
- Адреса не `http(s)`: `data:`, `blob:`, `chrome-extension:`, `chrome:`, `about:`.
- Загрузка, которая не открылась (`timeout` / `error`), ошибок JS и запросов не даёт: страница недогружена, ошибки
  неполные. Причина уже видна в сообщении шага.

**Исключения и консоль**
- `Script error.` без файла и строки (скрипт с чужого домена без CORS) — указать на поломку нельзя.
- `console.error` и `Log.entryAdded`, сообщение которых совпадает с подстроками из `browser-ignore.php`
  (например, `[Report Only]` у CSP в режиме отчёта).
- `Log.entryAdded` из источников `network` (это упавшие запросы, ловятся отдельно), `security` (mixed content — уже
  шаг `resources`), `violation`, `intervention`, `recommendation`, `deprecation` (предупреждения, не поломки).
- Уровни ниже `error` (warning, info, verbose) не собираются.

**Упавшие запросы**
- Сам документ страницы (основной фрейм): его код уже проверили `availability` / `crawl`.
- Отказы, вызванные самим браузером: `net::ERR_BLOCKED_BY_CLIENT`, `net::ERR_ABORTED`, `canceled = true`,
  `blockedReason` = `inspector` / `subresource-filter`.
- `blockedReason = mixed-content` — дубль находки `mixed_content`.
- Типы `Ping`, `CSPViolationReport`, `Preflight` и `/favicon.ico`, который браузер запрашивает сам (тип `Other`).
- `XHR` / `Fetch` с ответом 401 / 403: запрос к API без входа — ожидаемый ответ. 404 и 5xx — учитываются.
- 429: лимит запросов сработал из-за трёх загрузок подряд.
- Адрес уже есть среди битых ресурсов шага `resources` — дубль `broken_resource` (сравнение через
  `normalizeFindingLocation()`).
- **Повторная проверка:** `GET`-запрос типа `Script` / `Stylesheet` / `Image` / `Font` / `Media` после загрузок
  перезапрашивается один раз через `httpRequest()` (`HttpClient.php`, без изменений). Ответ < 400 — сбой был
  разовым, находки нет. Запросы других типов и методов (`POST` и т. п.) не перезапрашиваются: у них могут быть
  побочные эффекты. Сетевая ошибка без ответа у такого запроса становится находкой, только если повторилась
  минимум в 2 загрузках.
