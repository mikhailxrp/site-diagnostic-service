# Current Task

## Фаза
Phase 2 — Глубокая проверка и история

## Задача
Справочник актуальных версий скачивается командой `php bin/update-databases.php` и обновляется сам раз в неделю
(Планировщик заданий Windows); новый шаг `outdated` «Устаревшие версии» (сразу после `stack`) сравнивает с ним
найденные версии CMS, PHP и JS-библиотек, версии плагинов WordPress — онлайн с кэшем; заполняет
`stack_items.latest_version`, создаёт находки `outdated`, отчёт показывает дату базы.

## Образец
Образца нет: компоненты Tabler (решение владельца, 15.11.2026). Изменение экрана отчёта:
- элемент стека с версией: «актуальная: X»; устаревший — бейдж «устарела» / «ветка не поддерживается»;
- карточка «Стек», внизу: список баз «База версий — от ДД.ММ.ГГГГ» (список, чтобы базы уязвимостей тасков 7–8
  добавились без переделки); база старше 14 дней на момент диагностики → предупреждение «база не обновлялась —
  проверьте задачу Планировщика»;
- старая диагностика без шага `outdated` → как сейчас.

## Решения (16.11.2026, подтверждены владельцем; перепроверены на расширение)
- **Источники** (проверены запросом 16.11.2026):
  - ядро WordPress — api.wordpress.org/core/version-check (7.1.4);
  - PrestaShop, OpenCart — Packagist `repo.packagist.org/p2/…` (9.2.1, 4.1.0.4);
  - Joomla, Magento — GitHub releases (на Packagist их нет); пред-релизы (alpha / beta / rc / dev) отбрасываются —
    у Magento последний релиз `2.4.10-alpha1`; патчи `2.4.7-p3` — стабильные;
  - JS-библиотеки — npm `registry.npmjs.org/<пакет>/latest`: только последняя версия — полный документ пакета
    слишком большой (React 7 МБ при лимите HttpClient 5 МБ);
  - PHP (сверх плана, решение владельца) — php.net `releases/active.php`: последняя версия каждой поддерживаемой
    ветки; ветки нет в списке → не поддерживается (без ручного порога, обновляется само);
  - плагины WordPress — онлайн api.wordpress.org/plugins/info при диагностике, кэш 7 дней в
    `storage/cache/wp-plugins/`; «нет в каталоге» тоже кэшируется, сбой сети — нет (повторится в следующий раз)
  - нет источника: 1С-Битрикс (версия не видна), Shop-Script, Мегагрупп, InSales, Tilda (обновляет провайдер)
- **Одно место на элемент стека** — `data/version-sources.php`: ключ стека → источник, пакет / репозиторий,
  `eol_below` (порог ветки без поддержки, необязателен). Новая библиотека = одна строка. Начальные `eol_below`
  только где факт известен точно: jQuery < 3, Bootstrap < 5, Vue < 3, Lodash < 4, Joomla < 5, Magento < 2.4,
  PrestaShop < 1.7; у WordPress нет (только «устарела»); у PHP — из php.net
- **Сопоставление элемента стека с источником**: по `key` (CMS, библиотеки, WooCommerce); `category = php` → `php`;
  плагин с `parent = wordpress` → slug из имени (у WooCommerce — `plugin_slug`)
- **Устаревание**: версия ниже последней → «устарела»; мажорная ветка ниже последней → в тексте «отстала на
  мажорную версию»; ветка ниже `eol_below` / нет среди веток php.net → «ветка не поддерживается»
- **Серьёзности** — таблица констант в `OutdatedCheck.php` (как в SEO): ядро CMS — устарела `medium`, без поддержки
  `high`; PHP — `low` / `high`; JS-библиотека — `low` / `medium`; плагин WordPress — `medium`. Нет версии или
  непонятная версия (хэш вместо номера) → находки нет; плагина нет в каталоге (платный) → находки нет
- **Обновление баз — реестр источников** `getDatabaseSources()`: каждая база — ключ, файл, функция загрузки и
  разбора. Таск 7 добавляет Wordfence и retire.js записью в реестр, `bin/update-databases.php` не переписывается.
  По каждому источнику: загрузка → разбор → проверка (JSON, есть версия) → запись во временный файл → замена.
  Упал источник — его прошлые данные и дата остаются, остальные обновляются. Даты — по источникам; итог — в
  `app.log`; второй запуск при работающем первом сразу выходит (lock через `flock`, снимается сам при падении)
- **Где базы**: рабочая — `storage/databases/latest-versions.json` (в `.gitignore`); начальная в репозитории —
  `data/latest-versions.json` (первый запуск скрипта); нет рабочей → читается начальная (её дата → предупреждение
  о старой базе, если Планировщик не работает)
- **Отчёт**: `runStackStep()` кладёт id записанных `stack_items` в факты — шаг `outdated` проставляет им
  `latest_version`; базы, которыми пользовалась диагностика, → `summary_json.databases` (ключ базы → название,
  дата), отчёт выводит этот список целиком
- **Планировщик**: задача «Site Diagnostics — обновление баз», раз в неделю, PHP OpenServer, рабочая папка — корень
  проекта, «запускать при первой возможности, если пропущено» (ПК был выключен); повторный запуск `.ps1`
  обновляет задачу (`-Force`). Скрипт запускаю я в ходе таска (решение владельца)
