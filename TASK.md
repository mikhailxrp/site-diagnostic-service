# Current Task

## Фаза
Phase 4 — ИИ-анализ (таск 5 — Перезапуск ИИ-анализа) — ✅ Завершён

## Задача
Кнопка «Перезапустить ИИ-анализ» заново проходит три ИИ-шага (`ai_problem`, `ai_visual`, `ai_summary`) по фактам,
сохранённым в БД, и не делает запросов к проверяемому сайту. Работает и на старых диагностиках, где ИИ-шагов не было.

## Образец
Образца нет. Экран собирается из компонентов Tabler (решение владельца от 15.11.2026). Кнопка стоит в шапке
(`card-actions`) карточки «Итоговый вывод (ИИ)». Во время перезапуска показывается существующий экран прогресса.

## Как это работает
1. **POST `/diagnostics/{id}/ai-rerun`**. Порядок: CSRF → лимит частоты → атомарно `done → queued` (если диагностика
   не в `done`, запрос отклоняется с флешем) → воркер запускается в режиме «только ИИ» → redirect на
   `/diagnostics/{id}`.
2. **Воркер `bin/worker.php <id> --ai`**:
   - берёт диагностику `queued → running`, `started_at` не трогает;
   - одной транзакцией: добавляет недостающие ИИ-шаги в конец списка, сбрасывает существующие в `pending`
     (`message`, `started_at`, `finished_at` = NULL), удаляет находки `source = 'ai'`, ставит `progress = 0`;
   - выполняет только ИИ-шаги через `executeSteps()`, затем `finishDiagnostic(done)`.
3. **История в `ai_results` сохраняется.** Отчёт показывает только последний запуск: это уже делает
   `filterReportRunAiResults()` по `started_at` шага. «Потрачено на ИИ» по-прежнему суммирует все запуски.
4. **Если воркер не запустился**, статус возвращается в `done`. Шаги и находки к этому моменту ещё не тронуты.
