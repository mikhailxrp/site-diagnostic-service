# Current Task

## Фаза
Phase 5 — Для клиента и углублённые проверки (таск 7 — Повторная диагностика и сравнение)

## Задача
Добавить безопасный повтор завершённой диагностики с теми же исходными данными и экран сравнения двух завершённых диагностик одного сайта: какие проверяемые находки исправлены, остались или появились, как изменился стек и какие выводы отдельно дал ИИ.

## Образец
Утверждённого HTML-прототипа нет: каталог `.docs/ref/prototypes/` отсутствует. По принятому решению владельца экран сравнения и новые действия собираются из стандартных компонентов локального Tabler без собственных компонентов и новых стилей.

Состояния существующего экрана диагностики:
- завершённая или частично завершённая диагностика (`done` / `failed`) — в шапке доступна POST-кнопка «Повторить диагностику»;
- диагностика с `previous_id`, для которой доступно сравнение, — ссылка «Сравнить с прошлой»;
- `queued` / `running` и диагностика без доступного отчёта — действий повтора и сравнения нет;
- ошибка или превышение лимита повтора — пользователь остаётся на исходном отчёте и видит понятный флеш.

Состояния нового экрана сравнения:
- есть изменения — отдельные блоки «Исправлено», «Осталось», «Появилось», «Изменения стека» и «Выводы ИИ»;
- в одной из групп нет записей — внутри неё показано компактное пустое состояние, остальные группы не скрываются;
- изменений фактов и стека нет — явно показано, что проверяемые результаты совпадают;
- один из отчётов частичный (`failed`) — видимое предупреждение, что сравнение охватывает только собранные данные;
- неверные id, одна и та же диагностика, разные хосты, отсутствующие или незавершённые диагностики — экран не открывается, пользователь получает флеш и redirect на доступный отчёт либо в историю;
- ошибка загрузки или сборки — флеш без stack trace и redirect, полупустой экран сравнения не выводится.

## Как это работает
1. Добавляется POST `/diagnostics/{id}/repeat`. Контроллер первым делом проверяет CSRF, затем id, статус исходной диагностики и отдельный именованный лимит частоты — не больше 5 попыток за 60 секунд. Повтор разрешён только для статусов отчёта `done` и `failed`; `queued`, `running`, `cancelled`, отсутствующая или некорректная запись новую диагностику и воркер не создают.
2. Новая диагностика получает сохранённые нормализованные `url`, `host`, `problem_text` и `product_url` исходной записи. `previous_id` определяется непосредственно перед созданием существующим `findLatestDiagnosticIdByHost()` — так цепочка остаётся привязана к последней диагностике этого хоста, как при обычном запуске. Пользовательские значения из POST не принимаются. После создания запускается существующий полный воркер; при ошибке запуска новая запись переводится в `failed` тем же безопасным сценарием, что обычная диагностика, а пользователь получает флеш и переходит на её страницу.
3. Добавляется GET `/compare?a={id}&b={id}`, где `a` — базовая, `b` — более новая диагностика. Оба id проходят строгий разбор положительного целого числа; id должны различаться. Сравниваются только существующие `done` / `failed` диагностики с одинаковым сохранённым `host`. Ссылка из отчёта всегда формируется как `a=previous_id&b=current_id`; произвольный допустимый порядок параметров определяет направление сравнения и подписывается датами и адресами на экране.
4. Контроллер загружает обе диагностики, находки и стек через существующие модели. SQL во View, контроллерах и `DiagnosticComparer` не добавляется. Сервис сравнения получает готовые массивы и не обращается к БД, HTTP или сессии.
5. Проверяемые находки — записи `source != 'ai'`. Они дедуплицируются по непустому 40-символьному `fingerprint`: присутствует только в `a` — «Исправлено», в обеих — «Осталось», только в `b` — «Появилось». Для исправленных показываются данные старого запуска, для оставшихся и новых — актуальные данные `b`; порядок групп стабилен: по серьёзности, затем по заголовку и адресу. Записи с некорректным fingerprint не смешиваются с другими и безопасно пропускаются с записью warning в лог на уровне контроллера.
6. ИИ-находки (`source = 'ai'`) не объявляются исправленными или новыми: их формулировки и fingerprint могут меняться между запусками. Они выводятся отдельным блоком в двух подписанных колонках «Было» / «Стало» с заголовком, серьёзностью, деталями и расположением; пустое состояние поддерживается для каждой стороны.
7. Стек сопоставляется по нормализованной паре `category + name` без учёта регистра и внешних пробелов. Для совпавших элементов показываются изменения известной версии (`старая → новая`), для категории `plugin` — также новые и исчезнувшие плагины. Неизвестная версия не превращается в выдуманное обновление; дубли одного элемента объединяются детерминированно. Если стек не изменился, блок содержит явное пустое состояние.
8. Экран сравнения использует карточки, списки, бейджи серьёзности, alert и адаптивную сетку Tabler. Все значения из диагностик, находок и стека экранируются через `e()`. Ссылки на исходные отчёты и кнопка возврата доступны без JavaScript; собственный CSS и клиентская логика не добавляются.
9. На странице диагностики обе новые возможности отсутствуют в PDF-режиме. POST-форма повтора содержит `csrfField()`, а её кнопка и ссылка сравнения имеют зону нажатия не меньше 44 px. Действия не дублируются внутри отчёта и не влияют на существующие PDF, клиентский отчёт и перезапуск ИИ.

## Out of scope — не трогаем
- Изменение схемы БД, `previous_id`, алгоритма создания fingerprint и существующих записей диагностик, находок или стека
- Повтор только ИИ-анализа, логика `ai_results`, промпты RouterAI и попытка семантически сопоставлять разные формулировки ИИ
- Сравнение скриншотов, PageSpeed, шагов, времени выполнения, клиентских текстов, стоимости ИИ и содержимого `summary_json`
- Повтор из истории, массовые повторы, автоматический повтор по расписанию, отмена работающей диагностики и сравнение более двух запусков
- Изменение клиентского отчёта, PDF-экспорта, печатных стилей, постоянное хранение сравнений и экспорт сравнения в PDF
- Новые зависимости, JavaScript, собственные CSS-компоненты, миграции и попутный рефакторинг моделей, контроллеров, View или сервисов

## Definition of Done
- [x] POST повтора проверяет CSRF до чтения/изменения данных, принимает только положительный id и не доверяет значениям `url`, `host`, `problem_text`, `product_url` или `previous_id` из запроса
- [x] Для `done` и `failed` создаётся новая диагностика с теми же адресом, описанием и адресом товара; её `previous_id` указывает на последнюю диагностику этого host, запускается полный воркер и выполняется redirect на новый экран прогресса
- [x] Некорректная, отсутствующая, `queued`, `running` или `cancelled` диагностика не повторяется; при ошибке создания/запуска нет необработанного исключения и понятный флеш ведёт на подходящий существующий экран
- [x] Шестая попытка повтора за 60 секунд блокируется до создания записи и запуска воркера, событие пишется в warning-лог без URL, текста жалобы и других лишних данных; после истечения окна повтор снова доступен
- [x] GET сравнения принимает два разных положительных id; отсутствующие записи, одинаковые id, разные host и статусы вне `done` / `failed` дают понятный флеш и redirect без частичного рендера
- [x] Автотесты подтверждают классификацию фактов: fingerprint только в старой диагностике попадает в «Исправлено», в обеих — в «Осталось», только в новой — в «Появилось»; дубли не размножают строки, результат стабильно отсортирован
- [x] Для оставшейся находки экран использует актуальные заголовок, серьёзность, детали и расположение новой диагностики; все динамические значения экранированы, длинные адреса и тексты не ломают карточки
- [x] Находки `source = 'ai'` не попадают в три группы фактов и показаны отдельными списками «Было» / «Стало» без утверждения, что они исправлены или появились
- [x] Автотесты подтверждают изменения стека: смена известной версии показана как `старая → новая`, новые и исчезнувшие плагины разделены, отсутствие версии и дубли обрабатываются детерминированно, совпавший стек даёт пустое состояние
- [x] В отчёте `done` / `failed` есть POST-кнопка «Повторить диагностику» с CSRF; у диагностики с допустимым `previous_id` есть ссылка `/compare?a=<previous>&b=<current>`; у выполняемой диагностики, в PDF-режиме и при недоступном сравнении действий нет
- [x] Экран сравнения показывает адреса и даты обоих запусков, ссылки на исходные отчёты, три группы фактов, изменения стека, отдельный ИИ-блок и предупреждение для каждого частичного отчёта; отсутствие изменений и пустые подгруппы объяснены текстом

- [x] Ошибочные сценарии проверены реальными запросами: неверный CSRF, незавершённая диагностика, разные хосты, неверные/одинаковые id и превышение лимита не создают новую запись и не запускают воркер
- [x] Страницы диагностики и сравнения проверены на 360, 768 и 1280 px: горизонтальной прокрутки нет, зоны действий не меньше 44 px, длинные значения переносятся, консоль браузера чистая
