# PRD — Product Requirements Document

Дата: 2026-11-15
Источники: диалог (`/prd-init`), сайт провайдера https://routerai.ru/

## О продукте
**Название:** Site Diagnostics
**Что это:** личный инструмент для экспресс-диагностики интернет-магазинов потенциальных клиентов, сайты которых бросили разработчики. Вставляешь ссылку на сайт и, если есть, описание проблем. Сервис определяет стек, ищет поломки в коде и логике, сломанную вёрстку и плагины. На выходе отчёт: стек, найденные поломки и проблемы.
**Тип:** внутренний веб-инструмент (один пользователь), чистый PHP + MySQL.
**Деплой:** локально на ПК владельца (Windows), OpenServer. В интернет не выкладывается.

**Главный принцип:** факты собирает код (HTTP-запросы, разбор HTML, браузер без окна). ИИ только толкует собранные факты и смотрит скриншоты, а не придумывает находки. В отчёте у каждой ИИ-находки видно, на какие факты она опирается.

## Роли и доступ
| Роль | Кто это | Что может |
|---|---|---|
| Владелец | ты сам (и пользователь, и администратор) | всё: запускать диагностики, смотреть и выгружать отчёты, историю, менять настройки и ключи API |

## Страницы / разделы
| Путь или название | Описание | Доступ |
|---|---|---|
| Новая диагностика | форма: ссылка на сайт + описание проблемы | владелец |
| Диагностика (ход и отчёт) | прогресс проверки, затем полный отчёт: стек, поломки, проблемы, скриншоты, ИИ-вывод | владелец |
| Клиентская версия отчёта | тот же отчёт простым языком для владельца магазина | владелец |
| Экспорт в PDF | скачивание полного или клиентского отчёта | владелец |
| История | список прошлых диагностик с поиском по адресу сайта | владелец |
| Сравнение | две диагностики одного сайта рядом: что исправлено, что появилось | владелец |
| Настройки | провайдер ИИ (RouterAI), модели по задачам, ключи API (только просмотр) | владелец |

## Главный сценарий
1. Владелец открывает сервис на своём ПК (входа нет: пользователь один, сервис доступен только с этого ПК).
2. Вставляет ссылку на магазин и, если есть, описание проблемы со слов клиента (например, «не оформляется заказ»).
3. Сервис проверяет доступность сайта (коды ответа, редиректы, SSL, время ответа).
4. Определяет стек: CMS и версию, сервер, PHP, JS-библиотеки, тему, плагины и модули.
5. Обходит ключевые страницы: главная, каталог, товар, корзина.
6. На каждой странице ищет битые ресурсы, PHP-ошибки в выводе, ошибки JS и упавшие запросы, делает скриншоты на нескольких ширинах.
7. Проверяет сценарий «товар → корзина → оформление» без отправки заказа.
8. Дополнительно проверяет устаревшие версии, уязвимости, открытые служебные файлы, базовое SEO и скорость.
9. ИИ сопоставляет описание проблемы с фактами, смотрит скриншоты и пишет вывод: что сломано, насколько серьёзно, с чего начать ремонт.
10. Владелец получает отчёт: стек, найденные поломки и проблемы. При необходимости выгружает клиентскую версию в PDF.

### 2. Запуск диагностики
- [ ] Форма: ссылка на сайт (обязательно) + описание проблемы (необязательно).
- [ ] Проверка, что ссылка корректна и сайт отвечает.
- [ ] Диагностика идёт в фоне, на экране виден прогресс по шагам [допущение: фоновый запуск нужен, т.к. проверка с браузером и ИИ длится минуты].

### 3. Доступность сайта
- [ ] HTTP-коды ответа, цепочка редиректов (http→https, www/без www).
- [ ] SSL: действует ли сертификат, срок окончания, mixed content.
- [ ] Время ответа сервера.

### 4. Определение стека
- [ ] CMS / платформа и её версия по признакам в HTML, заголовках, cookies, путях, мета-тегах, служебных файлах.
- [ ] Веб-сервер, версия PHP (если видна), CDN.
- [ ] JS-библиотеки и их версии (jQuery и др.).
- [ ] Тема (шаблон) и список плагинов / модулей, видимых снаружи.
- [ ] У каждого признака указывать, откуда он взят, и степень уверенности.

### 5. Обход страниц
- [ ] Автоматически находить и проверять ключевые страницы магазина: главная, категория каталога, карточка товара, корзина, оформление.
- ~~Ограничение числа страниц и щадящий темп запросов (из настроек).~~ Решение 15.11.2026: без лимитов.

### 6. Поиск поломок (без браузера)
- [ ] Битые ресурсы: CSS, JS, картинки, шрифты с ответом 4xx/5xx.
- [ ] PHP-ошибки, выведенные на страницу (Fatal error, Warning, Notice, Deprecated, трассировки).
- [ ] Устаревшие версии CMS, плагинов и библиотек, известные уязвимости по найденным версиям.
- [ ] Открытые служебные файлы по фиксированному списку: `.git`, `.env`, бэкапы и дампы, `phpinfo`, логи.
- [ ] Базовое SEO: robots.txt, sitemap.xml, title / description, canonical, noindex / nofollow.

### 7. Проверка в браузере (Chrome без окна)
- [ ] Ошибки JavaScript в консоли и упавшие сетевые запросы на каждой проверенной странице.
- [ ] Скриншоты страниц на ширинах 360 / 768 / 1366.
- [ ] Сценарий «товар → в корзину → оформление»: дойти до формы оформления, заказ **не отправлять**. Фиксировать, на каком шаге сломалось.
- [ ] Скорость загрузки через Google PageSpeed Insights (оценка и основные метрики).

### 8. ИИ-анализ (только по API, через RouterAI)
- [ ] Разбор описания проблемы и собранных фактов → гипотезы причин со ссылкой на факты.
- [ ] Проверка вёрстки по скриншотам → список визуальных поломок (съехавшие блоки, пустые места, наложения, сломанные слайдеры и т.п.).
- [ ] Итоговый вывод: что сломано, насколько серьёзно, с чего начать ремонт.
- [ ] Сохранять, какая модель дала ответ.
- [ ] Если ИИ недоступен или нет ключа, отчёт строится из фактов, без ИИ-разделов.

### 9. Отчёт
- [ ] Отчёт на экране: стек, поломки и проблемы с разделением по серьёзности, скриншоты, ИИ-вывод.
- [ ] Клиентская версия отчёта простым языком, без технических подробностей.
- [ ] Экспорт полного и клиентского отчёта в PDF.

### 10. История и сравнение
- [ ] История диагностик: список, поиск по адресу сайта, открытие старого отчёта.
- [ ] Повторная диагностика того же сайта и сравнение с прошлой: что исправлено, что осталось, что появилось.

## Не делаем
- Публичная ссылка на отчёт: сервис работает только локально, отчёт клиенту отправляется в PDF.
- Локальные модели (Ollama): модели подключаются только по API.
- Размещение на shared-хостинге и любом внешнем сервере.
- Несколько пользователей и ролей.
- Отправка тестовых заказов и любые действия, которые меняют данные на проверяемом сайте [допущение].
- Подбор паролей, сканирование портов, нагрузочные проверки [допущение].

## Данные (сущности)
- **Диагностика** — ссылка, описание проблемы, дата, статус, связь с прошлой диагностикой того же сайта.
- **Проверенная страница** — адрес, тип (главная, каталог, товар, корзина, оформление), HTTP-код, время ответа.
- **Найденный стек** — CMS, версии, плагины и модули, тема, библиотеки, источник признака, уверенность.
- **Находка (проблема)** — тип, серьёзность, где найдено, описание, на какие факты опирается.
- **Скриншот** — страница, ширина экрана, файл.
- **ИИ-вывод** — задача, модель, ответ, дата.
- **Настройки** — провайдер, модели по задачам; ключи API — в `.env`.

## Интеграции
- **RouterAI** (https://routerai.ru/): единый OpenAI-совместимый API к моделям GPT, Claude, Gemini и др. Модель выбирается параметром `model`, оплата в рублях. Нужен для разбора проблемы, проверки вёрстки по скриншотам и итогового вывода.
- **Google PageSpeed Insights API**: оценка скорости загрузки.
- **Google Chrome** на ПК в режиме без окна (из PHP, например через `chrome-php/chrome` [допущение]): скриншоты, ошибки JS, упавшие запросы, сценарий корзины.
- **Источник данных об уязвимостях по версиям CMS и плагинов**: какой именно, не известно (см. открытые вопросы).

## Ограничения
- Сроки, бюджет, юридические требования: не названы.
- Стек обязателен: чистый PHP + MySQL, без фреймворка.
- Окружение: OpenServer на Windows-ПК владельца.
- Проверка только внешняя, по публичным страницам. Доступа к коду и админке проверяемого сайта нет.

## Роадмап (примерный)

### Фаза 0 — Фундамент
- Проект запускается в OpenServer, есть подключение к MySQL, ядро на чистом PHP, логирование.
- Общий макет на Tabler (входа нет — решение 15.11.2026).
- Страница настроек (модели; ключи API из `.env` только для просмотра).
- Фоновое выполнение диагностики с отображением прогресса.

### Фаза 1 — Экспресс-диагностика
- Можно вставить ссылку и описание, запустить проверку.
- Видно, жив ли сайт: коды ответа, редиректы, SSL, время ответа.
- Видно стек: CMS и версия, сервер, PHP, библиотеки, тема, плагины.
- Видны битые ресурсы и PHP-ошибки на странице.
- Можно получить отчёт на экране.

### Фаза 2 — Глубокая проверка и история
- Проверяются ключевые страницы магазина, а не только главная.
- Видны устаревшие версии и известные уязвимости, базовые проблемы SEO.
- Все диагностики сохраняются, к ним можно вернуться.

### Фаза 3 — Проверка в браузере
- Видны ошибки JavaScript и упавшие запросы.
- Есть скриншоты на трёх ширинах экрана.
- Видна оценка скорости загрузки.

### Фаза 4 — ИИ-анализ
- Можно выбрать модель RouterAI для каждой задачи.
- ИИ связывает жалобу клиента с найденными фактами и предлагает причины.
- ИИ находит сломанную вёрстку по скриншотам.
- В отчёте есть итоговый вывод: что сломано и с чего начать.

### Фаза 5 — Для клиента и углублённые проверки
- Можно выгрузить отчёт в PDF и получить клиентскую версию простым языком.
- Можно повторить диагностику и сравнить с прошлой.
- Проверяется сценарий «товар → корзина → оформление».
- Проверяются открытые служебные файлы.
