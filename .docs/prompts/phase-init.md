# Регламент: планирование или перепроверка фазы

Применяй этот регламент, когда пользователь просит спланировать новую фазу или актуализировать существующую. Это внутренняя инструкция агента: копировать её никуда не нужно.

## Контекст

Прочитай:

- `AGENTS.md`;
- `.docs/prd.md` и `.docs/database.md`;
- `.docs/phases/_status.md`;
- существующие `phase-N.md`, чтобы учесть завершённую работу и принятые решения;
- `TASK.md` и `.docs/dev-log.md`, чтобы не потерять незавершённую или уже сделанную работу;
- `.docs/phases/phase-example.md` как шаблон структуры.

Для UI-тасков дополнительно прочитай `.claude/rules/design.md` (экраны собираются на локальном Tabler 1.6.1 без HTML-прототипов). Обязательно сверь план с фактическим кодом.

## Действия

1. Определи следующую фазу по запросу пользователя, PRD, статусам и незавершённым требованиям.
2. Сформулируй измеримый результат фазы для пользователя.
3. Раздели работу на независимо проверяемые таски разумного размера. Не дроби задачу только ради формального ограничения по числу файлов.
4. Для каждого таска укажи цель, предполагаемые файлы или модули, ограничения и проверяемый DoD.
5. Для UI-тасков укажи требуемые состояния экрана (нормальное, пустое, ошибка, частичный отчёт, PDF-режим — где применимо) и требования Tabler по `.claude/rules/design.md`.
6. При перепроверке сохрани выполненные таски и проектные решения, обнови только устаревшие или неподтверждённые части.
7. Запиши результат в соответствующий `.docs/phases/phase-N.md` и при необходимости обнови `_status.md`.

Если пользователь просил только предложить план, не изменяй файлы. Если просил создать или перепроверить документ, сделай запись без дополнительного подтверждения. Вопрос задавай только при неоднозначном продуктовом выборе, который нельзя разрешить по документации и коду.
