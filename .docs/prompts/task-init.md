# Регламент: подготовка активного таска

Применяй этот регламент, когда нужно подготовить `TASK.md` для следующего планового таска. Это внутренняя инструкция агента: копировать её никуда не нужно.

## Контекст

Прочитай:

- `AGENTS.md`;
- `.docs/phases/_status.md` и текущий `phase-N.md`;
- `.docs/dod-global.md`;
- `TASK-example.md`;
- существующий `TASK.md`, чтобы не потерять незавершённую работу;
- относящиеся к задаче файлы кода и тестов.

Для UI дополнительно прочитай `.claude/rules/design.md` (компоненты локального Tabler 1.6.1, обязательные состояния и режим PDF).

## Действия

1. Выбери первый ожидающий таск текущей фазы или тот, который явно указал пользователь.
2. Сверь описание с фактической реализацией: уже существующее не планируй повторно.
3. Сформулируй один проверяемый результат таска.
4. Укажи `Scope` — файлы, которые ожидается создать или изменить. Это границы работы, а не обязательство менять каждый файл.
5. Запиши `Out of scope`, включая следующие таски и попутный рефакторинг.
6. Составь конкретный `Definition of Done`: функциональные сценарии, автоматические тесты (на PHP 8.3 OpenServer), реальные проверки E2E и применимые критерии из `.docs/dod-global.md`.
7. Для UI опиши требуемые состояния экрана и совместимость с PDF-режимом (если экран участвует в экспорте).
8. Запиши результат в `TASK.md` по структуре `TASK-example.md`.

Не перезаписывай активный незавершённый таск без явного запроса. Если пользователь уже поручил подготовить следующий таск, отдельное подтверждение перед записью не требуется. Если продуктовое требование неоднозначно, сначала задай один содержательный вопрос.
