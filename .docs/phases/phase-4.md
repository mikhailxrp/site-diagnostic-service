# Phase 4 — ИИ-анализ

## Цель
ИИ через RouterAI связывает жалобу клиента с собранными фактами, находит сломанную вёрстку на скриншотах и пишет итоговый вывод; у каждой ИИ-находки видно, на какие факты она опирается.

## Статус
⏳ Ожидает

> План предварительный: перепроверить через `.docs/prompts/phase-init.md` перед началом фазы.
> Нужно: base URL RouterAI, ключ, модели по умолчанию и какие из них понимают картинки (открытый вопрос PRD).

## Таск 1 — Клиент RouterAI

**Статус:** ⏳ Ожидает

**Цель таска:**
Сервис отправляет запросы в OpenAI-совместимый API RouterAI с моделью из настроек, сохраняет каждый ответ и какую модель он дал.

**Что нужно создать/изменить:**
- `src/Services/AiClient.php` — `POST {ROUTERAI_BASE_URL}/chat/completions`, ключ `ROUTERAI_API_KEY` из `.env`, тайм-аут, повтор при 429/5xx, ответ в JSON-режиме, картинки как `image_url` (base64)
- `src/Models/AiResultModel.php` + таблица `ai_results`
- `src/Controllers/SettingsController.php`, `src/Views/settings/index.php` — кнопка «Проверить подключение» (список моделей / тестовый запрос)
- `tests/Unit/AiClientTest.php` — сборка запроса и разбор ответа без сети

**Definition of Done:**
- [ ] «Проверить подключение» показывает успех или текст ошибки от API
- [ ] В `ai_results` сохраняются модель, ответ, токены; ключ API нигде не сохраняется
- [ ] Нет ключа → ИИ-шаги `skipped`, отчёт строится из фактов
- [ ] Проверить `.docs/dod-global.md`

## Таск 2 — Пакет фактов и разбор проблемы

**Статус:** ⏳ Ожидает

**Цель таска:**
Шаг `ai_problem`: в ИИ уходит компактный список фактов с id и жалоба клиента; в ответ — гипотезы причин, каждая со ссылками на id фактов.

**Что нужно создать/изменить:**
- `src/Services/FactPacker.php` — факты (находки, стек, страницы) в JSON с id, обрезка по размеру
- `src/Services/Ai/ProblemAnalysis.php` — промпт, JSON-схема ответа, разбор
- `src/Services/Ai/EvidenceValidator.php` — ссылки только на существующие факты этой диагностики; гипотеза без ссылок отбрасывается
- `config/prompts/problem.txt` — текст системного промпта
- `tests/Unit/EvidenceValidatorTest.php`, `tests/Unit/FactPackerTest.php`

**Definition of Done:**
- [ ] Гипотезы сохраняются как `findings` с `source = 'ai'`, `category = 'hypothesis'`
- [ ] Гипотеза со ссылкой на несуществующий факт не попадает в отчёт (тест)
- [ ] Без описания проблемы шаг строит гипотезы только по фактам
- [ ] Проверить `.docs/dod-global.md`

## Таск 3 — Проверка вёрстки по скриншотам

**Статус:** ⏳ Ожидает

**Цель таска:**
Шаг `ai_visual`: скриншоты уходят в модель с поддержкой картинок; в ответ — визуальные поломки (съехавшие блоки, пустые места, наложения, сломанные слайдеры) со ссылкой на скриншот.

**Что нужно создать/изменить:**
- `src/Services/Ai/VisualAnalysis.php` — пачки скриншотов, уменьшение размера (GD), разбор ответа
- `config/prompts/visual.txt`
- `src/Services/Ai/EvidenceValidator.php` — проверка `screenshot_ids`
- `src/Views/components/finding.php` — у ИИ-находки миниатюра скриншота

**Definition of Done:**
- [ ] Находка `layout` открывает скриншот, на который ссылается
- [ ] Модель без поддержки картинок → шаг `failed` с понятной причиной
- [ ] Размер отправляемых картинок ограничен константой
- [ ] Проверить `.docs/dod-global.md`

## Таск 4 — Итоговый вывод и ИИ-разделы отчёта

**Статус:** ⏳ Ожидает

**Цель таска:**
Шаг `ai_summary`: что сломано, насколько серьёзно, с чего начать ремонт; в отчёте ИИ-блоки отделены от фактов и показывают модель и опорные факты.

**Что нужно создать/изменить:**

- `src/Services/ReportBuilder.php` — ИИ-разделы, ссылки «опирается на» с переходом к факту
- `src/Views/diagnostics/report.php`, `src/Views/components/ai-block.php`
- `src/Controllers/DiagnosticController.php` — «Перезапустить ИИ-анализ» без повторного обхода

**Definition of Done:**
- [ ] Итоговый вывод содержит план ремонта по шагам, у каждого пункта — ссылки на факты
- [ ] У каждого ИИ-блока подписано, какая модель его дала
- [ ] Перезапуск ИИ не делает новых запросов к проверяемому сайту
- [ ] Проверить `.docs/dod-global.md`
