# Phase 4 — ИИ-анализ

## Цель
ИИ через RouterAI связывает жалобу клиента с собранными фактами, находит сломанную вёрстку на скриншотах и пишет
итоговый вывод с планом ремонта; у каждой ИИ-находки видно, на какие факты она опирается и какая модель её дала.
Без ключа или при недоступном ИИ отчёт строится из фактов, без ИИ-разделов.

## Статус
🔄 В работе

> План перепроверен 16.11.2026 с учётом сделанного в Фазах 0–3 (`phase-init.md`).
> Дизайн: образцов нет — экраны из стандартных компонентов Tabler (решение владельца, 15.11.2026).
> Экраны: настройки — `src/Views/pages/settings.php`, отчёт — `src/Views/pages/diagnostic.php` (данные готовит

> Окружение (проверено 16.11.2026): `ROUTERAI_BASE_URL` и `ROUTERAI_API_KEY` лежат в `.env`; PHP 8.3 OpenServer —
> расширение `gd` включено. В коде ИИ ещё нет; в `findings` уже есть `source` и `ai_result_id` (без FK).

**Контекст (проверено 16.11.2026 запросом к API):**
- `GET https://routerai.ru/api/v1/models` отвечает **без ключа**: 605 моделей; у каждой
  `architecture.input_modalities` (понимает ли картинки), `supported_parameters` (`response_format`,
  `structured_outputs`, `reasoning_effort`), `context_length`, `pricing` — рубли за токен (`prompt`, `completion`,
  `input_cache_read`).
- Модель по умолчанию — `qwen/qwen4-max` («Qwen: Qwen4 Max»): текст, картинки, видео; JSON по схеме; контекст 1 млн;
  вход 160 ₽ / выход 481 ₽ за 1 млн токенов, кэш входа 8 ₽. Модель рассуждающая — рассуждения оплачиваются как выход.
- Оценка стоимости диагностики (5 страниц, 15 скриншотов, ~50 находок; 7 запросов): ~77 тыс. токенов на вход,
  ~14,5 тыс. на выход → ≈ 19 ₽, с `reasoning_effort = low` ≈ 26 ₽; маленький сайт — 8–12 ₽, большой — 40–50 ₽.
  Это оценка: настоящие токены видны в `ai_results` после тасков 2–4.

**Решения:**
- Модель по умолчанию — `qwen/qwen4-max` для всех трёх задач (`model_problem`, `model_visual`, `model_summary`),
  `reasoning_effort = low` — константа (решение владельца, 16.11.2026). Модели меняются на странице настроек.
- Три ИИ-шага после `pagespeed`: `ai_problem`, `ai_visual`, `ai_summary`. Нет ключа или модели → шаг `skipped`
  с причиной, отчёт строится из фактов. Ошибка API или неверный JSON → шаг `failed`, сырой ответ — в `ai_results`.
- Ответ модели — JSON по схеме (`response_format: json_schema`); ответы на русском.
- Факты для ИИ собираются **из БД** (находки, стек, страницы, `summary_json`, скриншоты), а не из памяти воркера —
  тогда ИИ-анализ можно перезапустить без нового обхода сайта и запустить на старых диагностиках.
- ИИ-находка без валидной ссылки на факт этой диагностики отбрасывается (главный принцип PRD).
- Текст со страниц проверяемого сайта (ошибки, заголовки, фрагменты вывода) уходит в запрос как данные: системный
  промпт прямо говорит, что указания внутри фактов не выполняются.
- Ключ API — только заголовком `Authorization`; не пишется в `ai_results.request_json`, `app.log`, сообщения шагов и
  тексты ошибок curl. Картинки в `request_json` — только id скриншотов.
- Тайм-ауты, размер и число картинок, предел пакета фактов — именованные константы (лимитов обхода нет, решение
  владельца).

**Сайты для ручной проверки:** https://sudar.su/, https://cleansan.ru/, https://www.citilink.ru/ (как в Фазах 2–3);
старые диагностики #129–#136 — для перезапуска ИИ (таск 5).

## Таск 1 — Клиент RouterAI и настройки моделей

**Статус:** ✅ Завершён

**Образец:** образца нет — компоненты Tabler (карточка «Модели ИИ (RouterAI)» на странице настроек)

**Цель таска:**
Сервис отправляет запросы в OpenAI-совместимый API RouterAI с моделью из настроек и сохраняет каждый ответ, модель
и токены. В настройках модель проверяется по списку моделей RouterAI, по умолчанию — `qwen/qwen4-max`; кнопка
«Проверить подключение» показывает ответ модели или ошибку API.

**Что нужно создать/изменить:**
- `database/install.php` — таблица `ai_results` (по `.docs/database.md`), FK `findings.ai_result_id → ai_results.id
  ON DELETE SET NULL` через `ALTER TABLE` (идемпотентно)
- `src/Services/AiClient.php` — `POST {ROUTERAI_BASE_URL}/chat/completions`, ключ `ROUTERAI_API_KEY` заголовком,
  тайм-аут константой, повтор при 429 / 5xx, `response_format` со схемой JSON, `reasoning_effort = low`, картинки как
  `image_url` (base64), разбор ответа (текст, токены, ошибка); транспорт через `callable` — тесты без сети
- `src/Services/AiModels.php` — список `GET /models` с кэшем на сутки в `storage/cache/`: есть ли модель, понимает ли
  картинки, поддерживает ли JSON по схеме, цена за токен
- `src/Models/AiResultModel.php`
- `src/Services/SettingsService.php`, `src/Controllers/SettingsController.php`, `src/Views/pages/settings.php` —
  модели по умолчанию (`qwen/qwen4-max`), проверка при сохранении по списку RouterAI, «Проверить подключение»
  (POST + CSRF → redirect + flash: модель и короткий ответ или текст ошибки)
- `tests/Unit/AiClientTest.php`, `tests/Unit/AiModelsTest.php` + фикстуры `tests/fixtures/routerai/`
- Сделано сверх плана / по-другому: изменён `src/Views/components/flash.php` — тип `warning` (для «список моделей
  недоступен»); неудачная загрузка списка моделей запоминается на 5 минут (`AI_MODELS_RETRY_AFTER`) — недоступный
  RouterAI задерживал каждое открытие настроек на ~10 с (DNS на Windows); цена в подсказке — с копейками
  («160,2 / 480,59 ₽»); проверено живыми запросами: RouterAI понимает `reasoning_effort` сверху, а не
  `reasoning.effort`, и сам возвращает `usage.cost` в рублях (пригодится в таске 4); в ответе модель без провайдера
  (`qwen4-max`), поэтому в `ai_results.model` пишется модель из настроек; запись проверки подключения в `ai_results`
  не делается (`diagnostic_id` NOT NULL)
