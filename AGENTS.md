# AGENTS.md — правила работы агента

Единая точка входа для ИИ-агентов в репозитории (Antigravity загружает этот файл автоматически; Claude Code подключает его через `@AGENTS.md` в `CLAUDE.md`).

## Проект

**Site Diagnostics** — локальный однопользовательский инструмент экспресс-диагностики интернет-магазинов.
Сервис собирает проверяемые факты через HTTP, разбор HTML и headless Chrome, а ИИ (RouterAI) используется только для их интерпретации.
Результат — технический или клиентский отчёт, сравнение запусков и экспорт в PDF.

### Окружение и инварианты

- **Среда:** Windows, OpenServer, PHP 8.3 (`C:/OSPanel/modules/PHP-8.3/PHP/php.exe`), MySQL 8 (`MySQL-8.2`). Локальный адрес: `https://service-diagnostic-site.local`. Проект не публикуется в интернете.
- **Без аутентификации:** входа, паролей и таблицы `users` нет (решение владельца). Защита: `Require local` в OpenServer, CSRF на POST-формах, атомарный файловый rate limit (`takeRateLimitAttempt()`).
- **UI на Tabler:** публичной части, `.docs/ref/prototypes/` и `.docs/design/` нет. Все экраны собираются из стандартных компонентов локального Tabler 1.6.1 + Tabler Icons 3.52.0 с минимальными стилями в `admin-theme.css` и `print.css`.
- **Секреты:** только в `.env` (читаются через `env()`). Никогда не хардкодить и не выводить в HTML, JSON, PDF или логи.
- **Тесты:** запускать на PHP 8.3 OpenServer (системный `php` в `PATH` может не иметь расширений `intl`/`gd`):
  ```powershell
  & "C:\OSPanel\modules\PHP-8.3\PHP\php.exe" vendor/bin/phpunit
  ```
  (или `composer test`, если PHP 8.3 OpenServer первым в `PATH`).

## Обязательные правила

Единый источник правил лежит в `.claude/rules/` и `.docs/dod-global.md` (Claude Code подгружает `.claude/rules/*.md` автоматически; в Antigravity открывай нужный файл перед изменением соответствующих файлов):

- `.claude/rules/general.md` — общие принципы кодирования для любой задачи;
- `.claude/rules/php.md` — обязательные правила для всех PHP-файлов, архитектуры Mini-MVC, безопасности и тестов;
- `.claude/rules/design.md` — обязательные правила для Views, Tabler, CSS, JS, PDF-режима и UI-проверок;
- `.docs/dod-global.md` — глобальные критерии готовности.

Не ослабляй эти правила и не заменяй их собственными соглашениями.

## Совместимость сред (Antigravity и Claude Code)

Регламент одинаков в обеих средах; различаются только встроенные инструменты:

- **Браузерная проверка UI:** проверяй реальные страницы на 360 / 768 / 1280 px и ошибки консоли любым доступным инструментом среды — в Antigravity через встроенного `browser`-субагента (или headless Chrome CLI), в Claude Code через Playwright MCP (если подключён) или headless Chrome CLI. Временные файлы и скриншоты после проверки удаляй (`.playwright-mcp/` в `.gitignore`).
- **Отслеживание задач:** для многошаговой работы используй встроенный трекер задач текущей среды, если он доступен.
- **Промпты из `.docs/prompts/`:** это внутренние регламенты агента — применяй их самостоятельно, не проси пользователя копировать тексты.

## Автономный рабочий цикл

### 1. Ориентация

1. Определи контекст задачи: плановый таск (`TASK.md` + `.docs/phases/_status.md` + `phase-N.md`) или отдельная задача/багфикс от пользователя (например, правки по ревью после завершения фаз 0–5).
2. Прочитай обязательные тематические правила (`.claude/rules/*`) и `.docs/dod-global.md` для затрагиваемых слоёв.
3. Изучи фактический код и существующие тесты, найди готовые хелперы и принятые шаблоны.

### 2. Планирование

Для нетривиальной задачи кратко определи порядок работ и затрагиваемые файлы. Не жди отдельного подтверждения обычных локальных обратимых действий в рамках уже выданной задачи.

### 3. Реализация

- Выполняй задачу целиком, а не останавливайся после анализа или плана.
- Для плановых тасков строго соблюдай `Scope` и `Out of scope` из `TASK.md`; для отдельных правок ограничивайся необходимыми файлами и не делай попутный рефакторинг.
- Если без изменения вне `Scope` задачу выполнить нельзя, объясни причину и согласуй расширение.
- Принимай обратимые технические решения самостоятельно, не меняя продуктовые требования.
- Сохраняй существующую архитектуру Mini-MVC и не добавляй внешние зависимости без необходимости.

### 4. Проверка

- Проверь каждый применимый пункт DoD из `TASK.md` (для планового таска) и `.docs/dod-global.md`.
- Запусти целевые тесты и полный прогон PHPUnit на PHP 8.3 OpenServer.
- Проверь исходный пользовательский сценарий end-to-end (реальные HTTP-запросы, UI или воркер), а не только статическим чтением кода.
- Для UI проверь состояния экрана, ширины 360 / 768 / 1280 px, зоны нажатия ≥ 44 px и чистоту консоли браузера.
- Проверь `storage/logs/app.log` на новые PHP errors и warnings, если выполнялся PHP-код.
- Не отмечай критерий выполненным без фактической проверки. Непроверенное или невозможное явно укажи в итоге.

### 5. Завершение

Когда все применимые проверки пройдены:

1. Для планового таска: отметь DoD в `TASK.md`, обнови статус таска в `phase-N.md`, а при завершении фазы — в `.docs/phases/_status.md`.
2. Для отдельного багфикса/доработки: не перезаписывай `TASK.md` без явного запроса.
3. Добавь запись сверху в `.docs/dev-log.md`: дата, что сделано, результаты проверок, следующий шаг.
4. В итоговом ответе кратко перечисли изменения, выполненные проверки и оставшиеся ограничения.

Если проверки не пройдены или реализация неполна, задачу не закрывай.

## Когда нужен вопрос пользователю

Спрашивай только если ответ нельзя получить из кода и документации и выбор влияет на результат:

- неоднозначное продуктовое требование с существенно разными вариантами;
- необходимое расширение `Scope`;
- рискованное, труднообратимое или внешнее действие (отправка реальных запросов/заказов, изменение продовых данных и т. п.);
- отсутствующие секреты или доступы.

Не спрашивай разрешения на чтение кода, локальное редактирование в рамках задачи, запуск тестов и исправление ошибок.

## Работа с Git и изменениями пользователя

Учитывай текущее состояние рабочей директории перед правками. Не перезаписывай и не откатывай чужие незакоммиченные изменения. Не выполняй `git commit`, `git push` и другие операции с историей Git без явного запроса пользователя.
